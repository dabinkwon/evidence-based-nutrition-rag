# 프로젝트 기준 정보

기준일: 2026-10-21. 최신 구현 상태는 [STATE.md](STATE.md), 상세 원안·PDF 요구사항 요약은 [이전 기록](../history.md) 참조.

## 목적·사용자 문제·가치 — 사용자 의도

- 프로젝트: **RAG 기반 일반 성인 식생활 관리 서비스**.
- 문제: 식생활 관리를 시작하는 성인이 식사량·영양 구성·음식 선택 이유를 판단하기 어렵다.
- 대상: 일반적인 식생활 관리를 시작하려는 성인.
- 가치: 공개 영양 데이터와 공식 지침을 근거로 계산 과정·추천 이유·출처를 확인할 수 있게 한다.
- 목표: 의학적 효과 입증이 아닌 계산의 검증 가능성과 문서 기반 설명, RAG 전후 품질 차이 확인.

## 범위 — 사용자 요구

### 최종 서비스의 사용자 흐름

사용자가 나이·성별·키·체중·활동량·선호·제외 재료를 입력하면, 검증된 공식으로 BMI·추정 에너지 필요량을 계산하고 조건에 맞는 음식·식단 후보를 제시한다. 섭취량별 영양 합계, 연결 근거가 확인된 레시피의 재료·조리법, 공식 지침에 근거한 추천 이유·출처를 함께 보여준다. 음식별 질문과 대체 음식 비교를 지원한다.

- 신체 정보·활동량 → 적용 대상이 확인된 에너지 계산의 입력. 음식 이름 연결 점수에는 사용하지 않는다.
- 선호 → 제외·영양 조건을 통과한 메뉴의 정렬 기준. 제외 재료 조건을 무시하지 않는다.
- 제외 재료 → 재료 원문·동의어·복합 재료를 검토하는 필수 조건. 알레르기 안전을 보장하는 기능으로 표현하지 않는다.
- 연결 미확인 레시피 → 참고 정보와 검토 후보로 구분하며, 일반 음식의 영양값을 해당 레시피의 정확한 값으로 표시하지 않는다.
- 현재 기초 구현과 검증 한계, 후속 계획은 [연결·개인화 명세](MATCHING.md) 참조. ‘정확도 향상’은 평가 전까지 목표다.

- 입력: 나이·성별·키·체중·활동량·음식 선호·제외 식재료.
- 제공: BMI·추정 에너지 필요량·음식/식단 후보·섭취량별 영양 합계·추천 근거·재료/조리법.
- BMI는 참고 지표이며 건강 상태나 에너지 필요량을 단독 판정하지 않는다.
- 계산은 입력 조건에 따른 추정값으로 표시한다.
- 제외: 질환 치료 식단, 급격한 건강 악화 원인 판단, 피부 증상 개선 처방.
- 전문가 조언을 대신하지 않는다는 안내를 제공하고 범위 밖 건강 질문에는 전문가 상담을 안내한다.

## 선택 기능과 제안

- F2015 RAG 전후 비교는 PDF상 심화지만 사용자 기획 목표에 포함한다. 대표 질문 5개 이상 비교 문서를 만든다.
- F2013 직접 HTML/CSS/JS UI·서버 분리, F2014 MMR: 미선택.
- F2016 서로 다른 외부 문서 출처 결합: 레시피 API와 지침 PDF 활용 계획과 관련 있으나 충족 여부 미검증.
- 제안: API 순서로 수집한 표본을 분류별로 보완하고 연결 검토표를 구성한다. 최종 메뉴 선정 방식은 미확정.
- 확정 방향(D006): 식단은 공식 원문으로 1인분 영양을 대조한 레시피 메뉴를 우선 구성한다. 일반 음식 API는 검색·비교용으로 유지하며 모든 메뉴의 API 간 연결을 요구하지 않는다. 조사 결과는 `docs/RECIPE_NUTRITION.md` 참조.

## 기술 구성·데이터 출처

- 현재 사용 코드: Python 표준 라이브러리 기반 수집기. 사용법·스키마·API 출처는 [data/README.md](../data/README.md).
- 계획 기술: Python 3.10+, Streamlit, ChromaDB, LangChain, LangGraph. 실제 RAG 의존성 설치·호환성은 미검증.
- 영양 데이터: 식약처 `FoodNtrCpntDbInfo03/getFoodNtrCpntDbInq03`; 명세 `data/api_spec.json`.
- 레시피: 식품안전나라 `COOKRCP01`; 원본·출처는 수집 보고서 참조.
- 식생활 설명 근거의 출처·이용 조건·활용 범위는 `data/guidelines/README.md` 참조. 영양소 섭취기준 전문·에너지 계산 기준은 별도 확보한다.
- 문서마다 기관·연도/버전·URL·이용 조건·사용 페이지를 기록한다. 버전과 적용 대상을 혼합하지 않는다.

## 계산과 RAG 역할 — 사용자 요구

- Python: BMI/에너지, 섭취량 환산, 영양 합계, 수치 조건·음식 ID·데이터 존재 여부 검증.
- LLM: 검색어 추출·색인 후보 문서 선별·확보한 근거로 설명. 수치를 임의 생성하지 않는다.
- 계산 기준표는 원문 대조한 구조화 데이터, 설명은 RAG 텍스트로 관리한다.
- 음식 메타데이터와 외부 문서는 두 컬렉션으로 분리한다. 관련 음식/식품군·문서 유형 필터를 설계한다.
- 세 프롬프트와 청크 크기·중복 길이·Top-k 설정을 분리하고 비교한다.

## 완료 판단 기준

- 필수 기능 F2001~F2012와 사용자 계산 기능이 실행 결과로 검증되어야 한다. 데이터 수집만으로 F2001 전체 완료로 판단하지 않는다.
- 단위·환산·합계·조건·제외 재료·적용 대상 검증, 재색인 중복 방지·캐시·항목별 기록 분리 확인.
- 원문과 주장 일치·인용 목록 일치·근거 부족 대응·서비스 안내를 확인한다.
- RAG 전후 동일 질문 5개 이상을 사실 정확성·근거 제시·불확실성 표현으로 비교한다.
- 성능 수치는 측정 후 기록한다. 체크리스트는 통과/실패/미확인으로 구분한다.
- 요구사항 정의서·파이프라인 설계·코드·README·실행 증거·셀프/상호 체크리스트·비교 결과를 정리한다.
