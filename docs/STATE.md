## 현재 목표

- 사용자 의도: 일반 성인 식생활 관리 RAG 서비스를 완성한다.
- 필수 후속 작업(W032): 요리 탐색 → 선택 레시피 확인 → 재료 영양 조회 → 사용량 계산 → 제외 조건으로 다른 요리 탐색 → 식생활 설명 → 개인 조건 반영의 일곱 질문 흐름을 구현한다. 모든 답변은 RAG 근거 기반, 계산은 검증된 근거로 Python 수행. 상세·현재 상태·완료 기준: [REQUIREMENTS.md](REQUIREMENTS.md)의 U001~U007. 대화의 후보 순서·선택 ID·제외 조건 유지와 재료 영양 데이터 확보 여부 점검이 필요하며 전체 흐름은 미완료다.
- 현재 단계: F2006~F2008 UI 제외 구현・대표 검증(W038). LangGraph 검색/생성·선택 문맥·설정 Top-k·근거 번호/유형·실제 인용만 반환을 연결했다. 실제 recipe:28 생성 및 테스트 29개 통과. 활성 색인은 W036의 recipe_meta 100·source_docs 1건 그대로이며 일반 지침/다른 항목 수집 범위 확대와 전체 생성 평가는 후속이다.

## 확인된 구현 상태

- `scripts/collect_nutrition.py`: 영양 API 수집·필드 정규화·ID 중복 제거·필수 수치 검사·JSON/CSV 저장.
- `scripts/collect_recipes.py`: 레시피 수집·재료/단계 추출·ID 중복 제거·JSON/CSV 저장.
- 두 스크립트는 Python 표준 라이브러리 사용. 키 환경변수명·실행법은 `docs/FILES.md` 참조.
- 음식 100개·레시피 100개와 원본·수집 보고서가 존재한다. 기존 API 호출 성공은 수집 당시 대화와 파일로 확인했다.
- 영양 음식 확장본 759개(초기 100개 포함, 추가 고유 659개), 메뉴 카탈로그 100개, 이름 기반 후보 21쌍(19개 레시피), 확정 연결 0건. 기존 음식·레시피 파일 보존.
- 입력 구조·제외 재료/일부 동의어 검출·선호 정렬을 구현했다. 에너지 모델은 없으며 최종 추천은 모두 차단 상태다.
- `scripts/audit_recipe_basis.py`: 공식 PDF와 API의 1인분 표기·5종 영양값·수량 포함 재료 문장 대조. `data/recipe_serving_menus.json`에 통과 메뉴 6개 저장.
- `data/guidelines/`: 공공누리 제1유형 웹 텍스트 5건·근거 17개. 2025 실천 점검자료 추가, 2026 자료는 정책 배경 한정. 계산 기준 아님.
- `scripts/recipe_rag.py`: 현재 검색 문서 101개(레시피 100·새 근거 1) 구성·제외 검사·선택 메뉴 우선·Responses 생성·인용 ID 검사. 기본 Chroma 검색은 선택 항목과 관련 자체 문서를 함께 반환한다. --retriever semantic/lexical은 이전 기준선이다.
- `scripts/index_vectors.py`: 두 ChromaDB 컬렉션 재생성·고정 ID upsert·원본 삭제 반영·실제 count·관련 항목 메타데이터 저장. 새 수집을 반복해도 현재 100·1건 유지. DB·임베딩 캐시는 Git 제외다.
- `scripts/collect_source_docs.py`: 기존 API 원본 100개·공식 본문 5개를 제한 환경의 제공 문서 묶음으로 사용. 프롬프트1/2·JSON 검증·자체 문서 우선·검색어별 캐시·설정 기반 청킹 구현. config/rag_sources.json과 docs/FILES.md W036 참조. 실시간 웹 검색/신규 크롤링은 미구현이다.
- `scripts/semantic_search.py`: `text-embedding-3-small` 임베딩·SQLite 캐시·컬렉션별 Top-3. 실행/평가 방법은 `docs/FILES.md`, 고정 실행 결과는 `docs/SEMANTIC_RESULTS.md` 참조.
- `scripts/rag_graph.py`: 실제 LangGraph retrieve/generate 두 노드·선택 메타데이터 무조건 문맥 보존·ID 중복 제거·근거 번호/유형. config/rag_answer.json에서 Top-k·최소 유사도 조정. --generate는 실제 인용 출처만 반환하고 무인용/실패 안내를 제공한다(W038).
- 계산·UI·생성 답변 품질 전체 평가는 미구현/미검증. 검색어 추출/후보 선별/답변 생성 프롬프트는 분리 구현했다. UI와 왼쪽 색인 건수 표시는 후속 보류한다.
- Git 저장소의 역할별 초기 커밋을 구성했다(W018). 초기 Git 미설정 상태는 과거 이력이며, 원격 push·PR은 수행하지 않았다.

## 재개 주의

- `data/sources/samsam_01.pdf`는 삭제 상태를 유지하고 복구하지 않는다. PDF 감사 스크립트는 원문 부재 시 중단한다. Downloads 사용자 파일은 미변경.

- 음식/레시피 각각 100건이 확보되었어도 서로 대응하는 메뉴 100쌍이라는 뜻은 아니다.
- 영양값은 한 끼가 아닌 100g 기준. 결측을 0으로 대체하거나 레시피 수치와 혼합 계산하지 않는다(D002).
- 수집 명령 재실행 시 기존 결과를 갱신한다. 검토 완료 데이터를 덮어쓰기 전에 보존 방식을 정한다.
- 네트워크 제한 시 실행 환경의 승인 절차를 따른다. 키·요청 URL·예외 원문을 출력하지 않는다.
- 새 LLM은 `AGENTS.md`와 이 파일부터 읽는다. 기록 문서 전체/원본 데이터 전체를 자동으로 읽지 않는다.
