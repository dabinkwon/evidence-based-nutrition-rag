# 현재 상태와 인수인계

마지막 갱신일: 2026-10-21

## 현재 목표

- 사용자 의도: 일반 성인 식생활 관리 RAG 서비스를 완성한다.
- 현재 단계: 공식 웹 문서 5건·근거 17개 확보. 허용 확인 후보만 등록, 식약처 신규 후보는 링크 메타데이터만 보관한다(W017). RAG 색인 전 단계다.

## 확인된 구현 상태

- `scripts/collect_nutrition.py`: 영양 API 수집·필드 정규화·ID 중복 제거·필수 수치 검사·JSON/CSV 저장.
- `scripts/collect_recipes.py`: 레시피 수집·재료/단계 추출·ID 중복 제거·JSON/CSV 저장.
- 두 스크립트는 Python 표준 라이브러리 사용. 키 환경변수명·실행법은 `data/README.md` 참조.
- 음식 100개·레시피 100개와 원본·수집 보고서가 존재한다. 기존 API 호출 성공은 수집 당시 대화와 파일로 확인했다.
- 추가 영양 음식 759개, 메뉴 카탈로그 100개, 이름 기반 후보 21쌍(19개 레시피), 확정 연결 0건. 기존 음식·레시피 파일 보존.
- 입력 구조·제외 재료/일부 동의어 검출·선호 정렬을 구현했다. 에너지 모델은 없으며 최종 추천은 모두 차단 상태다.
- `scripts/audit_recipe_basis.py`: 공식 PDF와 API의 1인분 표기·5종 영양값·수량 포함 재료 문장 대조. `data/recipe_serving_menus.json`에 통과 메뉴 6개 저장.
- `data/guidelines/`: 공공누리 제1유형 웹 텍스트 5건·근거 17개. 2025 실천 점검자료 추가, 2026 자료는 정책 배경 한정. 계산 기준 아님.
- 계산·음식별 검색 텍스트·임베딩·Vector DB·세 프롬프트·LangGraph·UI·품질 비교는 미구현.
- Git 저장소의 역할별 초기 커밋을 구성했다(W018). 초기 Git 미설정 상태는 과거 이력이며, 원격 push·PR은 수행하지 않았다.

## 진행 중인 작업

- 최근 자료 교체 조사(W015): `docs/RECENT_SOURCE_CANDIDATES.md`. 신규 후보는 이용 조건·본문 확보가 남아 기존 2020~2021 근거를 아직 교체하지 않았다.

- 최신 보충 웹 자료 수집·근거 위치 확인 완료. PDF 기반 과거 레시피 감사 결과는 보존하나 로컬 원문 재검증은 불가하다(W012).

## 막힌 문제와 필요한 정보

- 인증 장애는 수집 당시 없었음. 이번 기록 작업에서 API를 재호출하지 않았다.
- 영양 표본이 밥·빵·면에 편중되어 최종 메뉴 선정 기준이 필요하다.
- 레시피 6개는 1인분 기준 확인, 나머지 94개·g 환산·재배포 이용 조건·공식 계산식은 미확인이다.
- 사용자 확인이 필요한 팀/개인 기여·교육 일정은 기능 작업과 별개로 미확인 상태를 유지한다.

## 재개 주의

- `data/sources/samsam_01.pdf`는 삭제 상태를 유지하고 복구하지 않는다. PDF 감사 스크립트는 원문 부재 시 중단한다. Downloads 사용자 파일은 미변경.

- 음식/레시피 각각 100건이 확보되었어도 서로 대응하는 메뉴 100쌍이라는 뜻은 아니다.
- 영양값은 한 끼가 아닌 100g 기준. 결측을 0으로 대체하거나 레시피 수치와 혼합 계산하지 않는다(D002).
- 수집 명령 재실행 시 기존 결과를 갱신한다. 검토 완료 데이터를 덮어쓰기 전에 보존 방식을 정한다.
- 네트워크 제한 시 실행 환경의 승인 절차를 따른다. 키·요청 URL·예외 원문을 출력하지 않는다.
- 새 LLM은 `AGENTS.md`와 이 파일부터 읽는다. 기록 문서 전체/원본 데이터 전체를 자동으로 읽지 않는다.
